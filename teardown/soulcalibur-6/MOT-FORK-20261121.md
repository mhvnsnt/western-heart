# The .mot fork (Lane 1C, 2026-11-21) — why SCVI animations are NOT in this PR

**This is a genuine fork, reported with evidence. No converter was faked.**

## The claim

The SoulCalibur VI `.mot` animation format cannot be cracked in this lane
with the tools available on this box, and no public crack exists anywhere
searched live on 2026-11-21. Everything else in the teardown (movelists,
frame data, banks) is delivered; the motion data is the open item.

## Evidence

1. **No public crack exists.** Gildor's SC6 thread (live, crawled 12 days
   ago, unchanged since 2018): "nobody has cracked that yet, only meshes
   and textures" — umodel Anim = No. GitHub repo search for a SCVI .mot
   tool returns nothing (the only `.mot` extractor found anywhere is for
   NieR:Automata, a different game/format). FluffyQuack, the most active
   SCVI modder, on animation replacement: "there's little to no
   documentation" / "That might not happen anytime soon." The same
   Bandai Namco animation family (Tekken 7) has been uncracked
   community-wide for ~a decade — SCVI .mot is in the same position.
2. **The files are buried three layers deep, with no random access.**
   Verified live via HTTP range requests against the archive.org zip
   central directory (2026-11-21): the game is a FreeArc (`.dxn`) repack
   *inside* a deflate zip. `Data01.dxn` alone is 11,131,847,685 B
   compressed / 11,135,021,218 B uncompressed, stored deflate — and DEFLATE
   is sequential, so no single `.pak`, `.mot`, or exe byte can be fetched
   without streaming the full ~11.1 GB first. The `.mot` files themselves
   sit inside AES-encrypted UE4 `.pak` files inside that `.dxn`.
3. **No RE toolchain for the job exists on this box.** No Ghidra
   (`which ghidra`: nothing). No unarc/FreeArc tooling; apt is broken on
   this VM (per `~/TOOLS.md`). No umodel/quickbms binaries. Disk: 31 GB
   free of 150 GB (80% used) — a full extraction (11 GB download + ~11 GB
   unpack + multi-GB `.pak` handling) would consume the headroom and still
   leave the actual format RE undone.
4. **The crack itself is a research project, not a lane task.** It needs:
   the shipping exe's `.mot` loader disassembled (stripped UE4 shipping
   binary — no symbols), the compressed bone-track/quantization scheme
   reverse-engineered from real `.mot` samples, and a round-trip verifier
   (re-encode → byte-compare against source). The community has not done
   this in 8 years since release.

## What was done instead (closest complete thing)

- Pulled Scuffle whole (movelist bytecode + working parser + frame data)
  and ran it offline: **64,311 moves / 6,348 attacks / 5,360 attack moves
  for 22 fighters**, wired into WH banks.
- Every bank move carries its **.mot animation id** (`anim_ref:
  "scvi:<fighter>/anim-<id>"`). The movelist→animation mapping — the part
  that tells you *which* .mot file each move plays — is complete. Only the
  motion bytes inside those files are missing.
- Scuffle's own doc confirms the split: "Hitbox location and placement
  seems to be stored at least partly with the move animation" — i.e. the
  .mot holds hitbox placement too, so the .mot crack unlocks hitboxes as
  well as motion.

## What cracking it requires (for the owner / a future lane)

1. Get the game files locally with room to work (the in-repo release
   `soulcalibur6-archiveorg-20261106` holds the full 11.4 GB; a box with
   real disk headroom, or a cloud box, is needed — this VM's 31 GB free is
   not enough to download + unpack + extract `.pak`s comfortably).
2. Unpack the FreeArc `.dxn` (unarc/FreeArc on a machine that can install
   it), decrypt the UE4 `.pak`s (AES key is public in the Gildor thread),
   extract the `.mot` files + the shipping exe.
3. Disassemble the exe's `.mot` loader (Ghidra), derive the format, build
   an extractor, and prove it by round-tripping extracted animations
   against the source `.mot` bytes.
4. Wire the extracted clips into the banks via the `anim_ref` ids that
   this lane already put in place.

## Bottom line

Movelist + frame data: **done, in this PR, extracted — not estimated.**
Animation motion: **open, honestly blocked on the fork above.** Nothing in
this PR pretends otherwise.
