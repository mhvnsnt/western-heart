# JOB 1 VERDICT — NTPP descriptor factory: EXHAUSTIVE NEGATIVE

**Status: the population code does not exist in the EBOOT in the
form the brief hunted. Per the brief's stop rule, the hunt stops
here: no header-byte guessing, no textured GLB claimed, gate G3
(texture) NOT crossed.**

The round-13 contract is confirmed and extended — but every field
of the shared image descriptor is populated by **caller-supplied
scalars through parameterized constructors**, and no code path in
the EBOOT derives those scalars from NTPP/GIDX section bytes.

## What the descriptor actually is (all read this round, dis/ folder)

- The descriptor is an object with vtable `0x08bcfba0`; it embeds
  the round-13 texture object at **desc+0x10** (texobj vtable
  `0x08bd0690`, slot 4 = `0x08acc214`, the byte-size computer:
  size = w*h × TPSM factor(fmt&0xf), stored at texobj+0x10 —
  fmt 5 → ×1, fmt 7 → ×4, fmt <3 → ×2 path, fmt 3/4 nibble tables).
- Texture object layout (0x24 B): +0 vtable, **+4 descriptor ptr**,
  +8 CLUT ptr, +0xc GE list ptr, +0x10 byte size, +0x14, +0x18,
  +0x1c flags, +0x20. Ctor `0x08acc0a0`/`0x08acc0d8`; object ctor
  `0x08acc398` installs the vtable and stores the descriptor
  pointer it is *handed*.
- **The population API** — parameterized descriptor ctors
  `0x08acd9a0` / `0x08acda10` / `0x08acda80`:
  `(this, a1 -> +4, a2 -> sh +8 FORMAT WORD, a3 -> sh +0xa WIDTH,
  t0 -> sh +0xc HEIGHT, t1 -> sh +0xe)`, then they install the
  embedded texobj and tail-call `0x08acc318(this+0x10, 0, this)`.
  Default ctors `0x08acd8b8`/`0x08acd92c` write constants
  (+8 = −1, +0xa = 0, +0xc = 0, +0xe = 1).
- Everything above the parameterized ctors is pass-through:
  subclass ctors at `0x08acd3c0–0x08acd5a0` (vtable `0x08bd0b58`)
  and `0x08aec97c–0x08aeca68` (vtable `0x08bd0790`) set +0x34 to a
  global and forward arguments unchanged. The only direct jal
  callers of `0x08acd9a0` are themselves pass-through subclass
  ctors (`0x08acd490`, `0x08acd4f0`, `0x08aec9f8`, `0x08aeca38`).
  Above them: vtable dispatch only (texture/sprite library,
  0x08ac–0x08ae pages; the 0x08aec000 array class consumes
  descriptors via `0x08acc4b0`, the mip-level wrapper whose only
  callers are 0x08aec038/184/230/334/43c/544/73c).
- The NTPP/GIDX handler class (0x08acc214–0x08accb00, read in full)
  *consumes* descriptors; its registry entry sits at
  `0x08bcf7e0–0x08bcf7f8` (`'GIDX'`, `'eXt\0'`, `'NTPP'` as data
  words). RTTI names are data-only: `0x08b9c5b0` 'NTPP',
  `0x08b9c600` 'GIDX'. `0x08ab2bf4`, the vtable slot shared by all
  texture classes, is a bare `jr $ra` null stub.

## Search scope (the negative is bounded by exactly this)

1. Full read of the handler range 0x08acc214–0x08accb00, the
   descriptor class ctors/methods (0x08acd1bc–0x08acdc00), the
   0x08aec000 texture-array class, and every jal caller chain above
   the parameterized ctors (all pass-through).
2. **sh-triple scan (whole EBOOT): 0 hits** — no instruction window
   anywhere writes sh@+8, sh@+0xa, sh@+0xc to a common base register
   (the descriptor field triple). Descriptor fields are written
   field-by-field *nowhere* except the parameterized ctors.
3. **sw-cluster scan (whole EBOOT)**: 31 same-base sw@+8/+0xc/+0x28
   clusters; **every one triaged by direct disassembly** — VFPU
   matrix ops (0x08ad19d4, 0x08ad5cf0, 0x0881f340, 0x08aafde8,
   0x089d06c0 windows), zeroing ctors, a preset-table field copy
   (a0+0xc4 dest), a queue op, generic struct inits. None reads
   file or section bytes into descriptor fields.
4. **Magic-immediate scan**: no code compares the 'NTPP'/'GIDX'
   magics via lui/ori anywhere; dispatch is by registry table.
5. **Xref census** for the builders (0x08acce14/0x08acce50) and bind
   (0x08acd030): consumers only, as round 13 found.
6. **Data-side scan**: all NTPP sections in the regenerated
   top-76 set (19 top-level sections + idx24 slot 9's 40 embedded
   sections + idx02's texture package) searched at every 4-byte
   alignment for a serialized descriptor (fmt nibble ≤ 8, pow2
   dims, u32@+0x10 == w*h*bpp(fmt), u32@+0x28 in-section pointer):
   **0 hits in 59 sections**. The descriptor is a runtime object,
   never serialized into NTPP sections.

## Conclusion and residual

Per-section field derivation from NTPP bytes is **not present in
the EBOOT**: the game builds descriptors from (format, width,
height) scalars supplied by callers in the texture/sprite library
layer, which receives them through vtable-dispatched calls whose
origins are not section parsers. Where those scalars ultimately
come from for NTPP-carried images — most plausibly the same
runtime/asset-database path that round 12 already proved
capture-only for palette data — is the exact residual, restated:

> **RESIDUAL (Job 1):** NTPP image dimensions/format reach the
> shared descriptor as caller-supplied scalars via ctors
> 0x08acd9a0-family; no EBOOT code derives them from NTPP section
> bytes (exhaustive negative, scope above). Textured GLBs remain
> blocked on the same evidence class as round 12's palette
> verdict: a live GE capture or an asset-database source outside
> the EBOOT. Round 13's refusal of header-byte guessing stands.

(The data does contain one related hard fact for a future lane:
idx24's NTPP sections and the character NTPP packages hold their
GIDX pixel blocks under the round-10 chunk-tag scheme — pixels are
recoverable the moment dimensions are evidenced from any source.)
