## Method
1. Audit9: Ghidra's IMPORTED symbol table holds only 2 symbols (entry, vftable) — the XEX import
   table was NOT parsed into the PE import directory (import descriptors at file 0xf3a000 are zeroed).
2. Audit9c: getExternalSymbols() returns exactly 10 externals, EXTERNAL-space addrs 1..10, named
   EXT_FUN_00f58764/74/94/a4/c4, EXT_FUN_00f588c4/8984/8a34/8c84/9154. The names encode thunk VAs
   in the original XEX layout. No memory block covers 0x00f58764-0x00f59154 in the decrypted PE
   (thunk bodies were dropped by the XEX->PE converter), but `bl` call sites in .text target them.
3. Raw-file analysis: the IAT SURVIVES at file offset 0x400 (RVA 0x400, start of .rdata), 235 non-zero
   BE32 entries. Values are XEX-style (module<<16|ordinal): module 0 = xboxkrnl.exe (slots 0-68),
   module 1 = xam.xex (slots 71-233).
4. Stride hypothesis (VERIFIED): thunk VA = 0x00f58764 + 16*slot. Every observed `bl` call target
   (0x00f587a4/b4/c4, 0x00f58974/84/e4, 0x00f591c4/d4) is exactly 16-byte-aligned relative to
   0x00f58764 (remainders all 0x0). Standard 16-byte 360 thunk: lis/lwz/mtctr/bctr.
