# MPFB2 base family — proof run (2026-11-02)

What this PR wires: 6 MPFB2 macro bases become a selectable family in
the creation suite, via `tools/creation-suite/bases.json` (family
`mpfb2`) + `tools/mpfb2/select_base.py` + `tools/mpfb2/run_mpfb2_job.py`.
Selecting a base emits a suite job spec (`tool: "mpfb2-live"`) that
`tools/suite-jobs/run_job.py` dispatches to `run_mpfb2_job.py`, and a
fighter-JSON fragment (`F.mpfb2`).

This PR also fixes a broken dispatch: `run_job.py` already had the
override `"mpfb2-live" -> tools/mpfb2/run_mpfb2_job.py`, but that file
did not exist. It does now.

## Proof (pure Python, no Blender, no vendor checkout)

```
python3 tools/mpfb2/test_select_base.py
PASS: mpfb2 family — 6 bases selectable, job specs + fighter fragments
round-trip, dispatch resolves, validation + honest no-vendor failure verified

python3 tools/mpfb2/select_base.py list
MPFB 2 — CC0 base data, GPL-3.0 code
  mpfb2-super-heavyweight  male   Super Heavyweight (MPFB2)
  mpfb2-powerhouse         male   Powerhouse (MPFB2)
  mpfb2-technician         male   Technician (MPFB2)
  mpfb2-highflyer          male   High-Flyer (MPFB2)
  mpfb2-powerhouse-w       female Powerhouse (Women's, MPFB2)
  mpfb2-striker-w          female Striker (Women's, MPFB2)

python3 tools/mpfb2/select_base.py job mpfb2-powerhouse --out jobs/mpfb2-powerhouse.json
job spec -> jobs/mpfb2-powerhouse.json
run: python3 tools/suite-jobs/run_job.py --spec jobs/mpfb2-powerhouse.json
```

Example job spec (powerhouse): `{"tool": "mpfb2-live", "params":
{"macro": {"age": 0.5, "gender": 1.0, "height": 0.6, "muscle": 0.85,
"proportions": 0.6, "weight": 0.7}, "rig": "game_engine"}, "out":
"customization/templates/meshes/mpfb2-powerhouse.glb"}`. Macro values
are 0..1 per MPFB2's docs/entities/objectproperties.md (gender 0.0 =
female, 1.0 = male). The spec follows `run_mpfb2_job.py`'s actual
schema (`macro`/`rig` directly under `params`).

End-to-end dispatch was also exercised through `run_job.py` itself:
it dispatched `mpfb2-live` to the new runner, which failed honestly
with "MPFB2 not found. Run: bash tools/mpfb2/fetch-mpfb2.sh" and a
job status of `error` — no fake bake, no invented mesh.

## What is NOT proven here

- No baked MPFB2 mesh ships in this PR. `base_mesh` paths in
  bases.json are the jobs' output paths, not existing files.
- No live Blender bake was run here: that needs the vendor checkout
  (`bash tools/mpfb2/fetch-mpfb2.sh --with-blender`) and Blender 4.2+.
  The runner follows MPFB2's own `script_samples/` (create_human,
  macro set_value, reapply_macro_details, game_engine/rigify.human
  rig), but that code path is unexecuted until a machine with the
  vendor checkout runs it. Next run: fetch, then
  `python3 tools/suite-jobs/run_job.py --spec jobs/mpfb2-powerhouse.json`,
  then the standard export chain and a render proof.
- Skin/eyes/clothes asset packs are not applied by this job (they
  need the makehuman_system_assets pack); see `run_mpfb2_job.py`'s
  docstring. That is a follow-up job, not a silent skip.
