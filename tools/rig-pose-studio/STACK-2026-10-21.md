# Rig & Pose Studio — STEP 2: The Stack Standard

Status: **standard defined and committed**; implementation of the new
normalization stage is dispatched per-fighter from the STEP 1 audit (this
lane does not re-template fighters itself).

## The pipeline standard (owner TEMPLATE DIRECTIVE, 2026-10-21)

Every fighter, one flow — **no step may be skipped, and step 2 is the one
whose absence caused the Scarlett/Star failures:**

1. **INSPECT** — `tools/rig-pose-studio/glb_inspect.py` on the incoming
   model: joint set, rest rotations, rest world frame, weight sanity,
   skin presence. Output is recorded (audit JSON) before anything touches
   the model.
2. **NORMALIZE TO TEMPLATE** — the model's working skeleton becomes the
   house template skeleton fitted to the mesh: template = the **T7
   King-family 49-joint skeleton** (the de-facto house rig; A1/A3 verified
   joint-by-joint against T7 King's canonical rig; `teardown/tekken7/` is
   in the repo). Axis conversion happens ONCE, at the root, here — never
   smeared into per-bone rest rotations (the shipped-Star failure).
   - Foreign pro rigs that are canon (Scarlett's Daz G9 rig) are NOT
     re-skeletoned: they take the **adapter path** — clips are retargeted
     in rest-local space against their DEF skeleton via a verified bone
     map, or baked offline. The pipeline adapts; the model doesn't shrink.
   - The repo's `skeleton_template.json` (52-joint Mixamo T-pose) is
     **superseded as the house standard** by the T7 King-family template;
     it remains only as the GameRig backend's internal fit reference.
     GAP (logged): no fitted T8 template skeleton extracted yet — T8
     holdings are raw UE exports (kinpo-t8 244j, phantom-t8 311j,
     yukihyo 328j). Closing it = a teardown-lane extraction job.
3. **SKIN** — weights by heat diffusion (`blender-heat` / GameRig bone
   heat) for fresh fits; donor transfer (`knn` + `knn_smooth` +
   `diffuse_weights`, `apply_skin.py --rest-ref`) when a same-template
   donor exists. Donor and fitted rig must share the template — transfer
   across templates is how Leopard King got T3-baked folds.
4. **VALIDATE** — `tools/auto_rig/validate.py` + `pose_gate.py` + the
   rest-pose checks from `glb_inspect.py` (core rest rotations ~0 modulo
   documented template conventions; hips at template height; feet
   planted). A stretch gate alone is NOT acceptance (Leopard King passed
   stretch at 1.65–2.50 and read deformed) — gates screen, eyes decide.
5. **PROOF** — renders at the gate's worst frames
   (`tools/auto_rig/render_poses.py`), viewed by the producing lane
   before anything is reported.

## What already exists in the repo (evaluated, kept — not duplicated)

| Piece | Role in the standard |
|---|---|
| `tools/auto_rig/auto_rig.py` (6 backends) | The rigging engine room: `blender-heat`, `gamerig`, `knn`, `magicarticulate` (Apache-2.0, vendored), `unirig` (MIT, vendored), `puppeteer` (Apache-2.0, vendored). Licenses on file in each `VENDOR.md`. |
| `tools/auto_rig/rig_tripo_static.py` (PR #456) | **The intake one-command for unrigged statics**: codec decode → GameRig fit → weight smoothing → validate + anim gates → worst-frame renders → re-encode. Adopted as the standard intake for the audit's UNSKINNED class (scimitar, sun-ra-base, thor_alt1). Not duplicated by this lane. Its one gap vs the standard: it fits GameRig's Mixamo-convention skeleton — intake output must pass through NORMALIZE (step 2) before wiring; recorded here so the wiring step is never skipped. |
| `tools/auto_rig/backends/apply_skin.py --rest-ref` (PR #448) | Weight application with a rest reference — the rest-aware transfer the standard requires. |
| `tools/rig_repair/` | Per-defect repair kit (armpit, weldcap, swap_lr_joints, reskin_heat, stretch/diag tools) + `MODEL_DEFECT_TAXONOMY.md`. Kept as the repair bench; repairs run AFTER normalization, never instead of it. |
| `tools/anim-retarget/` | Clip retarget bench (bone maps, BVH trim, Blender retarget). Its world-delta path is **restricted by this standard**: valid only between template-aligned rest poses; cross-rest work goes rest-local or offline-bake. (Runtime `retargetClipToRig` is shared fighter code — the T3-crash-fix lane owns its bug; this lane changes no fighter code.) |
| `tools/jiggle/` | Secondary-motion bakes, scoped by fcurve audit (the Wiggle-2 audit pattern: hash-compare every curve outside the jiggle chains). |

## Not pulled (documented, per policy)

RigNet (GPLv3 copyleft), Auto-Rig Pro (commercial — documented, never
cracked), Pinocchio (superseded by Blender bone heat). AI backends need
CUDA (Kaggle/Colab runners in `tools/auto_rig/kaggle/`); on this VM the
CPU backends (heat, GameRig, KNN) are the production path.

## Proof status

The stack's components carry their own shipped proofs (PR #456's Zui A1
intake run + renders; GameRig baek example; #448's skin transfer). This
lane's end-to-end proof of the STANDARD (inspect → normalize → skin →
validate → render on one of the audit's drifted models) is the STEP 4
acceptance's job, executed through the owner's own controls (STEP 3) —
deliberately: the first full run of the standard is the owner fixing a
real defect with it, not a lane demo on a scratch file.
