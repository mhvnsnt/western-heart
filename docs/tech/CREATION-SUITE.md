# Creation Suite — Tekken 7 structure, multi-game parts, body physics

One shared creation suite (`packages/creation-suite`) serves Western Heart first,
then Bannon, AshLane and Brutal-Fist. This doc records how it is built, what
comes from which game, and the 2026 practice it follows.

## 1. Tekken 7 customization, recreated from the game's own tables

Source: the T7 Steam extraction (PR #863 → private mirror
`mhvnsnt/game-reverse-engineering` PR #51). Parser:
`tools/extract/t7/t7_customize.py <tkdata list dir> <out> [<models dir>]`.

| Table | Layout | Records |
|---|---|---|
| `customize_item_data` | 64-byte records; slot code at `+0x11` | 23,548 items |
| palette | RGB swatches, 12×12 grid | 144 |
| `color_rules` | 24-byte records | — |
| `chara_list` | 24-byte records | — |
| `preset_table` | 408-byte records | — |

Container: `u64 string_table_offset, u64 count, records…, strings`; record
size = `(offset-16)/count`.

Slot codes (proven against the item table and the mesh tokens) live in
`src/t7layout.js` and match the SPINE `t7` ids in `src/slotmap.js`:

`1 hed · 2 har · 3 hef · 4 oph · 5 gla · 6 fac · 7 fah · 8 fam · 9 bdu · 10 bdf ·
11 bdl · 12 opu · 13 opl · 14 exp · 15 unique · 17 aura · 18 skin tone · 19 mirror`

**Menu flow** (`T7_FLOW`): fighter → attire (A1–A4) → region tab → slot → item →
color (base/sub/trim layers, 144-swatch palette) → pattern → equip.
**Region tabs** (`T7_REGION_TABS`): Head [1–8], Upper Body [9,10,12], Lower
Body [11,13], Body [18,19], Effects [14,15,17]. The ui2 root menu now renders
the equipment list in exactly these tabs, then the Western Heart extra slots.

**Part swapping on the rig** (`src/rigswap.js`): T7 builds a fighter from
separate SkinnedMeshes all bound to one skeleton (MODEL_00 / BODY_SCALE__group /
BASE / Spine1 …, ~207–252 joints). A swap re-binds the part's meshes to the
live body's bones *by name* (`SkinnedMesh.bind` with a new `Skeleton`), removes
whatever was in that slot, and refuses parts under 90 % bone coverage (the
viewer then falls back to the socket attach). Part-only joints follow their
nearest ancestor the body has. Proven privately: Lee assembled from bdl + bdu +
fac + har (92–100 % coverage), then Paul's upper body (97 %) swapped onto Lee.

## 3. Size-adaptive jiggle (chest, glutes, belly, thighs)

`src/secondary.js` (spring system modelled on VRMC_springBone: stiffness, drag,
gravity, sphere colliders) tuned by `src/regions.js` (`physicsFor` scales by
`(girth/ref)^3`, so a bigger region is heavier and swings more). New: the ui2
viewer builds it on every fighter/body change (`viewer.rebuildPhysics`,
sliders from `physicsSliders()`), steps it per frame, and the root menu has a
**BODY PHYSICS** on/off row showing the live spring count.

## 4. 2026 practice followed (sources)

- VRM spring bones as the open standard for secondary motion — VRMC_springBone 1.0 spec: https://github.com/vrm-c/vrm-specification/tree/master/specification/VRMC_springBone-1.0
- `@pixiv/three-vrm-springbone` (MIT, v3.5.5, updated July 2026) as the reference three.js implementation: https://www.npmjs.com/package/@pixiv/three-vrm-springbone · https://pixiv.github.io/three-vrm/docs/modules/three-vrm-springbone
- Shared-skeleton part swapping + slot culling in a web character creator — M3-org CharacterStudio (MIT, three.js): https://github.com/m3-org/CharacterStudio
- Parametric body + spring presets + per-region tuning, headless — Hamr (MIT): https://github.com/hrabanazviking/Hamr
- three.js `SkinnedMesh.bind` / `Skeleton` (used for re-binding by name): https://threejs.org/docs/#api/en/objects/SkinnedMesh
