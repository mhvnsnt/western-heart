## Disagreements resolved (file wins)

1. #1039 body claim "0 newly-broken string hits" vs measured: FALSE
   under step-resolves-to-playable-move semantics. Newly-dangling steps
   (main -> reconciled unresolved): pantera 1->4, burger 7->11,
   demonio 20->24, diablo 24->28, kinpo 10->11, phantom 10->24,
   scimitar 6->8, skull 12->26. Deciding source: #1039's T8 purge wins
   — EVERY newly-dangling step is a stance/up move whose main anim_ref
   was `t8:` and which now sits in quarantine (e.g. pantera `d+1`,
   phantom `KIN.1`/`KIN.2`, skull `SLS.2`/`SWA.2`/`uf+2`, burger
   `BAL.1`/`uf+1`). Strings are left as-is (no silent deletion, no
   invented replacement); the T7 replacement key is UNMAPPED pending a
   walk-verified motbin cancel-table join. #1039's test never checked
   string resolution, only chord rows, so its chord claim still holds.
2. T8 refs remaining in #1039 playable content: provenance only, not
   playable data. `t8:` merge_source strings remain (pantera 7, burger
   7, demonio 47, diablo 9, kinpo 7, phantom 8, scimitar 8, skull 6) plus
   notes mentioning T8 frame data. Deciding source: file provenance is
   kept (deleting it would destroy the audit trail); anim_refs and
   damage are T7/T3/MOD. No Heat mechanic data found in playable moves;
   3 moves carry T8 mechanic NAMES only (demonio `Heat Seeker`,
   kinpo/phantom `Heat Burst`) — names, not mechanics; renaming them
   is a canon/name lane decision, not made here.
3. External MOD notation-join mismatches (Lane 2 / mvlt files joined to
   playable inputs by notation): pantera 15, burger 0, demonio 8,
   diablo 13, kinpo 2, phantom 9, scimitar 5, skull 6 (single-damage
   rows only; multi-hit rows counted separately, never called
   mismatches). NOT applied. Deciding source: the in-file t7 block
   (wired, cites TheBigTuna) wins over a notation-only join, which is
   not move-identity proof — e.g. demonio `f,n,d,d/f+2` in-file
   t7.damage 20 vs Lane 2 25, diablo `f,n,d,D/F+3` in-file 47 vs
   Lane 2 25, and generic `u/b+4` playable 11 vs Lane 2 12-33 by
   fighter. Two of these are wired-block conflicts (both sides cite
   TheBigTuna); overwriting by notation would be a guess. Listed here
   as UNRESOLVED for a move-id join, not silently fixed.
   Annotation-only differences (`32(37)`, `50?`, `~25?`) were resolved
   by comparing the numeric core — those are NOT mismatches.
4. "Jumping in standing slot" first pass flagged 9 moves; re-examination
   with word-boundary tokens clears all of them: `Lair` does not contain
   the token `air` (diablo/skull `Demon Lair`/`Lair's Dance`); jumping
   throws are grapple slots, not strikes (diablo `Jumping Powerbomb`
   x3); dash/run jump moves are not plain standing (burger `f,F+3`
   `Jumping Beans`, kinpo `f,f,f+3` `Spinning Jump Kick`). Remaining
   review bucket (dash/run/crouch-dash jump names): pantera 1, burger
   1, diablo 2, kinpo 1, phantom 1 — review, not violations.
5. Pantera "165 mid defaults": UNVERIFIED, not used. Measured on main
   pantera.json (874 moves): moves carry NO hit_level field at all;
   t7 blocks give hit_level for 248 moves, exact `mid` for 64,
   mid-prefixed for 100. #1039 changed zero hit_level values
   (base -> #1039 diff = 0). Reconciled pantera (768 moves): 248 with
   hit_level, exact `mid` 64 (same). Hit_level coverage for all
   reconciled fighters is in the validation report; anything beyond
   the t7 blocks is UNMAPPED.
6. Motbin playable join: 0 joins. Playable anim_refs (`t3:`/`t7:`/
   `UNMAPPED:t7-clip-pending`) do not match motbin anim names, and no
   join was made by name similarity (forbidden, and #1048's own rule).
   The `t7_motbin` layer is the verified wiring; the input-key join
   needs a .mvl display walk and is UNMAPPED work, not done here.
